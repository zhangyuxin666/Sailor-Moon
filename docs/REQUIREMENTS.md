# 活动管家需求与验收标准

## 产品目标

管理者用一句话描述活动，系统自动完成规划、工具执行和结果交付。系统减少写策划、建表、分工、催办、提醒和复盘等重复工作，同时让参与者在统一平台查看并完成自己的任务。

## 用户角色

- 管理者：创建组织和班级、导入成员、发起活动、确认方案、查看进度、发送催办、取消提醒、生成复盘。
- 参与者：查看分配给自己的活动任务和班级待办、提交文件或说明、更新完成状态。
- 报名者：无需登录即可通过公开链接填写活动报名表。
- 系统服务：Worker 执行 Agent 工作流，Scheduler 投递到期提醒，QQ Gateway 接收被 @ 的消息。

## 核心流程

1. 管理者登录并选择班级，用一句话描述想完成的事务。
2. Agent 判断意图和复杂度，补全信息并生成可编辑草案，不立即产生副作用。
3. 管理者修改并确认草案后，系统选择最小合适流程：作业、通知、信息收集或复杂活动。
4. 复杂活动由 Agent 读取真实班级成员，生成活动方案、时间、物料、任务和负责人。
5. Worker 幂等执行选中的工具：创建报名表、落库任务、生成日历、创建提醒、发布 QQ 群通知。
6. 报名者提交表单；参与者在平台完成分配任务；管理者实时查看统计和执行步骤。
7. 管理者可手动催办，或取消尚未发送的定时提醒。
8. 活动结束后，系统基于报名人数与任务完成情况生成复盘。

## 功能要求

### 活动策划

- 输入为一句自然语言活动需求。
- 输出包含标题、活动流程、活动时间、注意事项和物料清单。
- AI 分工只能选择当前班级中的真实参与者。

### 报名与统计

- 自动创建公开报名页和分享链接。
- 收集姓名、联系方式和扩展信息。
- 管理者查看报名人数和明细，其他账号不得查看。

### 任务分工

- 每项任务包含标题、负责人和状态。
- 参与者在个人工作台查看被分配的活动任务并标记完成。
- 管理者查看整体完成比例并通过 QQ 群催办。

### 日历与提醒

- 自动生成可下载的 ICS 日历文件。
- 活动前创建定时提醒，服务重启后恢复未执行任务。
- 提醒可在发送前取消，发送前再次检查状态。

### 活动复盘

- 汇总报名数据、任务完成情况和执行结果。
- 输出亮点、数据回顾和改进建议。

## Agent 编排

工作流固定为规划、执行、交付三个阶段：

1. 规划：自然语言转结构化方案。
2. 执行：依次调用表单、任务、消息、日历和提醒工具，每步记录状态。
3. 交付：把方案、报名入口、任务、提醒和执行日志呈现在管理平台。

## 工程要求

- 幂等：同一活动、同一工具和同一内容使用稳定幂等键，重试不重复创建或发送。
- 重试：只重试网络错误、限流等瞬时错误；业务和权限错误立即失败。
- 权限：生产环境仅接受登录会话，活动必须属于账号可管理的组织和班级。
- 隔离：组织、班级、成员、活动、任务和文件均有明确归属。
- 可观测：后台任务、Agent 步骤、QQ 投递和关键管理操作可查询。
- 安全：密码哈希、登录限流、安全 Cookie、同源校验、文件限制和审计日志。
- 恢复：数据库和文件可备份，Worker、Scheduler 和 QQ Gateway 可自动重启。

## 验收场景

1. 管理者从 Excel 导入两名成员并创建活动，AI 生成的负责人只能是这两名成员。
2. 同一后台任务重复执行，不会重复创建报名表或重复发送相同消息。
3. 非活动所有者不能查看报名统计、取消提醒或生成复盘。
4. 参与者只能更新分配给自己的活动任务。
5. 已取消提醒即使到期也不会发送。
6. Scheduler 重启后仍能恢复未到期提醒。
7. 管理者能查看报名、任务、提醒、消息投递和 Agent 步骤的最新状态。
8. 活动结束后生成的复盘包含最新报名数和任务完成结果。
