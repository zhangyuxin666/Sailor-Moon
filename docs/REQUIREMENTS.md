# 活动管家功能分析与需求

本文用于课程功能分析、开发和验收对照，描述当前产品范围与应满足的规则；条目存在不代表已完成全部验收。系统边界见 [架构说明](ARCHITECTURE.md)，请求与响应以 [API 契约](API.md) 为准，操作流程见 [用户手册](USER_GUIDE.md)。

## 1. 目标与范围

系统面向班级、社团中的作业、通知、信息收集和活动协作。管理者输入自然语言，先得到可修改的结构化草案，确认后由业务后端建立待办或执行活动流程。参与者查看本人任务、提交材料、签到和反馈；无需账号的报名者通过公开链接报名。

运行架构为 Java 21 / Spring Boot 3.5.16 业务后端及 WAR、React 18 前端、内部 FastAPI AI/RAG、PostgreSQL 16 + pgvector，以及可选 QQ Gateway。业务权限、数据库写入和工具副作用由 Spring 决定。没有模型密钥时保留确定性离线建议；没有 QQ 配置时应能完成站内业务。

## 2. 角色与权限

- **管理者**：初始化组织、管理有权限的班级与成员、导入名册、生成并确认草案、查看待办进度、管理自己创建的活动、知识和模板。登录角色不等于拥有任意组织或任意活动的权限。
- **参与者**：查看本人的班级待办、活动任务和可参与活动；提交本人作业材料、完成本人任务、签到、提交或修改本人反馈。
- **公开报名者**：读取公开表单，填写姓名、联系方式和动态问题，凭本人回执查询或取消自己的报名。
- **系统服务**：持久化工作流和提醒、领取后台任务、调用内部 AI 和 QQ 网关、保存步骤、投递结果与审计。模型输出不能授予用户权限。

四人主责和协作边界见 [TEAM.md](TEAM.md)，不能按 Java 或前端整个目录划给一个角色。

## 3. 主要用例

### 3.1 首次使用、班级和成员

管理者在首次访问时创建首个账号、组织并确认隐私政策；之后使用账号密码登录。创建班级后可下载 Excel 模板并整批导入成员。导入先校验整批内容，已有账号仅在满足当前组织、有效状态和参与者角色条件时复用，不能借导入取得跨组织账号。

初始或重置密码要求先修改，修改后重新登录。管理者重置密码须检查目标的组织归属；个人设置提供改密、隐私数据和审计入口。会话失效时页面重新登录并保留尚未提交输入，用户明确重试原操作。

### 3.2 自然语言草案与人工确认

管理者选择班级后描述事务，系统判断 assignment、notice、survey 或 activity，选择合适的最小工作流。草案允许修改标题、说明、时间、题目、任务和流程开关，显示模型/离线模式、检索状态和来源版本。

发布必须使用人工确认的快照。缺少活动必要信息时进入等待补充，不能用臆造日期、空任务替代确认。作业缺截止时间时先补全。AI 负责人候选只能来自真实班级账号 ID，不能凭同名推定身份。

### 3.3 作业与待办

参与者查看分配给自己的待办，提交文字说明和可选文件；管理者查看已交/未交情况并访问授权文件，可催办、设置或取消尚未发送的提醒，导出未交名单。上传应校验大小、类型、配额和归属；猜测文件地址不能获得其他人的材料。

### 3.4 活动编排与任务协作

确认复杂活动后建立活动、运行和后台队列记录，按受限工具执行规划、表单、任务、日历、提醒和消息交付。详情展示业务运行与执行队列的不同状态、真实步骤和安全错误，支持补充输入、恢复、失败重试和取消。

任务包含标题、说明、截止时间、优先级、负责人、前置依赖和状态。负责人必须是当前有效成员；无法确认的人选保留待分配。管理者可指派、改派和查看工作量建议；参与者只更新分配给本人的任务。依赖不能包含自身、其他活动任务或环。

### 3.5 报名与活动变更

公开表单保留题目顺序、类型、选项和必填规则，服务端验证回答。支持容量、截止、开放/关闭、规范化身份防重复和取消释放名额。报名成功给出回执和取消凭证，其他报名者不能据公开页读取完整名单。

活动创建者查看完整回答（包括历史字段）和统计，可调整规则、改期或整体取消。改期协调日历版本和提醒；取消阻止后续执行与新业务操作，保留已完成和在途事实，不声称撤回已发送外部消息。

### 3.6 签到、反馈和复盘

签到、反馈默认关闭。创建者在就绪活动保存开放设置时确认并追加当前有效成员快照。成员离班后保留既有签到和统计历史，但不能继续操作；后来加入的成员须再次保存开放设置才能进入快照。

成员从“签到与反馈”操作本人记录；真实班级成员中的 manager 也可以本人签到，无需成为活动创建者。代签仅允许活动创建者为当前合资格成员操作。结束活动停止新签到且不扩充快照，保留允许反馈的设置；已取消活动拒绝新提交。反馈限当前有效、已入快照且已签到的成员，评分为 1–5 整数，可按版本修改本人反馈。

复盘从数据库取得报名、任务、到场和评分聚合，保存统计快照、正文、版本及生成/降级信息，刷新后仍可查询历史。反馈原文不进入模型。生成复盘与结束活动是独立操作；结束关闭报名、签到及未发送提醒。

### 3.7 知识库、模板与导出

管理者维护本组织知识资料并检索本组织及公共资料，显示来源版本。正文和向量同步更新，历史来源未知的向量需重新索引；离线或检索不可用须明示。

业务模板包含只读内置模板和本组织模板。可从自己的草案/活动提取脱敏结构，编辑通用内容并保存；应用到有权限的班级仅生成新草案，重新确认日期、负责人及发布行为。

活动创建者可导出报名和任务 CSV，班级管理者可导出待办未交名单。下载复查当前权限，使用中文 BOM、完整历史回答与公式防护；不输出取消凭证、密码、会话或内部 metadata。

### 3.8 QQ、日历与通知

QQ 为可选渠道。管理者先在设置取得绑定码，在群内完成绑定，再在成员管理中明确选择本组织授权群。发送、提醒和入站查询均复查当前授权。日历提供 ICS，改期保留 UID 并递增版本。

站内通知按账号投递。外部投递保存持久意图、结果和网关日志，未知结果停止自动重发并由授权入口核对。平台未配置、权限失败或实际结果未知都必须显示真实状态。

## 4. 非功能要求

- **一致性**：关键活动变更先锁活动；请求标识重放、资源版本和唯一约束共同防止重复写入与静默覆盖。
- **可靠性**：后台队列持久化，Worker 有独立心跳、领取凭证和执行上限；进程恢复复用已提交步骤，有限重试不能抹去取消或未知投递事实。
- **安全与隔离**：会话 Cookie、密码哈希、登录限制、来源校验、组织/班级/账号级授权及审计；内部服务使用不同令牌，模型仅接收必要上下文。
- **可用性**：管理者和参与者入口清晰，桌面及窄屏可操作；加载、空数据、权限、失败和版本冲突有说明，失败保留输入。
- **可运维性**：健康与就绪检查、结构化步骤和投递查询、数据库迁移、持久卷与备份恢复流程可追溯。
- **可维护性**：API、前端类型、迁移和团队文档随变更同步；真实环境验证与单元测试分别记录，不以测试数量替代业务验收。

当前代码未声明经压测验证的并发容量、吞吐或可用性指标；课程交付不应虚构这些数据。双 Tomcat 提供节点切换演示，共享数据库和单网关仍有各自边界。

## 5. 验收场景与边界

以下为验收目标，执行结果应另外附环境、版本和证据：

1. 新环境初始化、创建班级并导入成员；初始密码登录要求改密，跨组织账号不能被导入或重置。
2. 使用真实成员生成草案，修改后发布，执行结果使用确认快照；缺日期进入补充流程。
3. 参与者仅查看和完成本人任务/待办，越权读取活动统计和附件被拒绝。
4. 重复与并发报名不超额、不重复；必填/选项校验有效，取消回执释放名额。
5. 改期更新日历与提醒；取消在步骤边界生效，并保留已发送事实。
6. 重复执行或 Worker 接管复用已提交结果，过期凭证不能回写；QQ 未知结果先核对。
7. 成员本人签到、创建者代签、成员变动和结束状态均符合快照规则；未签到不能反馈。
8. 生成复盘不自动结束活动；复盘历史持久化，AI 服务失联时明确降级且不传反馈原文。
9. 知识检索不越组织，模板应用仅产生草案；CSV 在授权后下载且不暴露内部凭据。
10. 按部署模式保存并恢复数据库、附件和网关日志后，实际核对数据、文件下载和恢复状态。

本地离线集成、PostgreSQL单机/双节点、独立备份恢复及浏览器关键流程已完成验证。真实QQ平台和生产模型质量仍须相应实网证据；远端GitHub Actions结果须首次推送后确认。
